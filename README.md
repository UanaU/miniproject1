# 우리집 관리비 스마트 분석기

같은 아파트 단지 입주민이 로그인 후 본인 세대 관리비를 조회·등록하고, 같은 평수 평균 / 같은 평수+가구원수 평균 /
전월 / 작년 동월과 비교해보는 웹 서비스.

## 기술 스택

- 백엔드: Django + Django REST Framework, MySQL (PyMySQL)
- 프론트엔드: React (Vite) + Recharts
- AI 원인분석: Google Gemini API (`google-genai`). 키가 없거나 호출/파싱에 실패하면 폴백 문구를 대신 보여준다

## 준비

1. MySQL에 데이터베이스 생성 (최초 1회)

   ```bash
   mysql -u <user> -p -e "CREATE DATABASE apartment_fee CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
   ```

2. `.env.example`을 `.env`로 복사하고 값 채우기 (`DB_USER`/`DB_PASSWORD` 등, `GEMINI_API_KEY`는 있으면 입력)

## 백엔드 실행

```bash
python -m venv venv
venv\Scripts\activate          # Windows
pip install -r requirements.txt

cd backend
python manage.py migrate

# 더미데이터 생성 (최초 1회 또는 재현이 필요할 때)
cd ..
python generate_dummy_data.py

# 더미데이터 DB 적재 (재실행 시 기존 데이터 초기화 후 재적재)
cd backend
python manage.py load_dummy_data

# DB 불변식 검증 (선택)
python manage.py verify_data

python manage.py runserver
```

백엔드는 `http://localhost:8000` 에서 실행된다.

## 프론트엔드 실행

```bash
cd frontend
npm install
npm run dev
```

프론트엔드는 `http://localhost:3000` 에서 실행된다.

## 로그인 테스트 계정

`user0001` ~ `user1000` / 비밀번호 `pw10001` ~ `pw11000`

## 화면 구성

- **로그인** (`/login`) — 아이디/비밀번호 로그인, 하단에 회원가입 링크. 로그인 성공 시에는 항상
  **마이페이지**로 이동한다 (관리비 데이터 유무와 무관)
- **회원가입** (`/signup`) — 아이디/비밀번호/이름/연락처/동(더미데이터 기준 101~115동 중 선택)/호수/
  평수(18·24·32·38·45·52평 중 선택)/가구원수 입력 후 로그인 화면으로 이동 (자동 로그인 아님, 가입한
  계정으로 다시 로그인해야 함)
- **마이페이지** (`/mypage`) — 내 정보 조회, "정보 수정" 버튼으로 수정 화면 이동
- **마이페이지 수정** (`/mypage/edit`) — 이름/연락처/동/호수/평수/가구원수 수정 (아이디는 변경 불가)
- **관리비 조회** (`/fees`) — 청구년월 선택, 항목별 관리비 표시. **전기세/수도세/가스비** 값 옆의
  "수정" 버튼을 누르면 해당 행이 바로 입력 필드로 바뀌어 그 자리에서 값을 고쳐 저장할 수 있다
  (저장 시 합계금액 자동 재계산). 좌측의 **합계금액/전기세/수도세/가스비** 항목을 클릭하면 우측에
  해당 항목의 **선택한 청구년월이 속한 연도(1~12월)** 추이가 꺾은선 그래프로 표시된다
- **관리비 등록** (`/fees/register`) — 세대별 항목(전기세/수도세/가스비)만 입력하면 단지공통·동공통 항목은
  동일 청구년월(없으면 최근월)의 다른 세대 값을 기준으로 자동 반영되어 새 관리비 레코드를 등록
- **관리비 비교** (`/fees/compare`) — 청구년월을 고른 뒤, 비교 기준을 큰 탭 두 가지 중에서 고른다
  - **내관리비에서 비교**: 내 과거 관리비와 비교 — 전월 / 작년 동월
  - **다른세대와 비교**: 다른 세대와 비교 — 같은 평수 평균 / 같은 평수+가구원수 평균
    (선택 시 상단에 기준이 되는 평수·가구원수를 안내)

  각 탭마다 **총관리비/전기세/수도세/가스비** 4개의 막대그래프가 그려지고, 그래프 하나에는
  **이번달 + 그 탭의 비교 대상 2개, 총 3개의 막대**가 서로 다른 색으로 표시된다 (예: "내관리비에서 비교" 탭의
  "총관리비 비교" 그래프 = 이번달·전월·작년 동월 막대 3개). 비교 대상 데이터가 없으면(예: 입주 1개월차라
  전월/작년 동월 기록이 없는 경우) 해당 막대만 제외하고, 둘 다 없으면 "비교 데이터 없음"을 표시한다.
  화면 하단에는 AI 원인분석 카드가 있어, 이번달/전월/작년동월/같은평수평균/같은평수+가구원수평균 데이터를
  근거로 Gemini가 "내 관리비 비교"와 "다른 세대와 비교" 결과를 종합해 증가 원인과 계절에 맞는 절약팁을
  알려준다 (자세한 내용은 아래 "AI 원인분석 방식" 참고. API 키가 없거나 실패하면 안내 문구로 대체)

로그인 후에는 화면 우측 상단에 **마이페이지** / **내관리비** 메뉴와 **로그아웃** 버튼이 항상 표시된다.
**내관리비**를 클릭하면 보유한 관리비 레코드가 하나도 없을 때는 **관리비 등록** 화면으로, 데이터가 있으면
**관리비 조회** 화면으로 이동한다 (하위 메뉴에서 관리비 조회·관리비 등록·관리비 비교로 바로 이동 가능).
로그아웃 시 로그인 화면으로 이동한다.

### 그래프 표시 방식

꺾은선 그래프(관리비 조회)와 막대그래프(관리비 비교) 모두 Y축이 **0원부터 시작하지 않고 실제 값의
최소~최대 범위 근처로 좁혀서(줌인해서)** 그려진다. 값 변화나 이번달 대비 비교 차이가 실제 금액 차이보다
시각적으로 더 뚜렷하게 보이도록 하기 위함이다 (`frontend/src/utils/chart.js`).

- **꺾은선 그래프**(관리비 조회의 항목별 연간 추이): `computeTightDomain`으로 값 범위 근처로 축을 좁히고,
  범위가 좁아 눈금이 겹칠 수 있을 때는 소수점 한 자리(`formatAxisTick`)를 붙여 표시한다
- **막대그래프**(관리비 비교의 이번달 + 비교 대상 2개, 총 3개 막대): `computeStepDomain`/`buildStepTicks`로
  Y축 눈금을 **정확히 500원 간격**으로 고정해서 그린다 (모든 눈금을 생략 없이 표시)

### AI 원인분석 방식

`backend/llmanalysis/services.py`의 시스템 프롬프트가 Gemini에게 요구하는 것:

1. **종합 판단** — "내 관리비 비교"(전월·작년 동월)와 "다른 세대와 비교"(같은 평수 평균·같은 평수+가구원수
   평균) 데이터를 모두 받아, 두 시각을 함께 고려한 종합 요약을 작성한다 (예: "지난달보다는 늘었지만 이웃
   평균보다는 낮다"). 프론트엔드(`AnalysisCard.jsx`)도 이 5개 항목(이번달/전월/작년동월/같은평수평균/
   같은평수+가구원수평균)을 모두 API에 전달한다
2. **수치 기반 서술** — "요약"과 "항목별원인" 모두 구체적인 금액(원)과 비율(%)을 근거로 작성하도록 강제한다.
   항목별원인은 항목×비교기준 조합별로 증감률 절대값이 5% 이상일 때만 포함하고, 하나도 없으면 빈 배열로
   두는 대신 "요약"에 수치로 그 사실을 명시한다
3. **계절/월 인지 절약팁** — "이번달"의 청구년월(YYYYMMDD)에서 월을 읽어 계절(봄/여름/가을/겨울)을 판단하고,
   그 계절에 맞는 구체적인 절약팁(예: 여름 냉방, 겨울 난방)을 우선 제시하도록 지시한다

API 키가 없거나 응답 파싱에 실패하면 항상 안내 문구(`FALLBACK_MESSAGE`)로 대체되어, 데모 중 오류로 화면이
깨지지 않는다.

## API

- `POST /api/accounts/login/`, `POST /api/accounts/logout/`, `POST /api/accounts/signup/`
- `GET /api/accounts/me/` (내 정보 조회), `PATCH /api/accounts/me/` (내 정보 수정)
- `GET /api/managementfee/summary?year_month=YYYYMMDD` — 이번달/전월/같은평수평균/같은평수+가구원수평균/작년동월
- `GET /api/managementfee/history` — 내 전체 보유 개월의 합계금액/전기세/수도세/가스비 시계열
- `POST /api/managementfee/register` — 청구년월 + 전기세/수도세/가스비(+ 납부상태)로 신규 레코드 등록
- `PATCH /api/managementfee/record?year_month=YYYYMMDD` — 전기세/수도세/가스비 중 보내온 항목만 수정하고
  합계금액을 재계산 (관리비 조회 화면의 인라인 수정에서 사용)
- `POST /api/managementfee/ai-analysis` — 이번달/전월/작년동월/같은평수평균/같은평수+가구원수평균 데이터를
  보내면 Gemini가 이를 종합한 원인 요약·항목별원인·계절 맞춤 절약팁을 반환 (관리비 비교 화면의 AI 원인분석
  카드에서 사용)
